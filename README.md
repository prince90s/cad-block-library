# cad-block-library

从杂乱 CAD 母库（DWG）提炼可复用图块图例库的 WorkBuddy 技能。

把一张堆积了几十个图层、几百个块定义的施工图母库，提炼成「**块名不改、图例不变、图层干净、插入即居中**」的图块图库。

典型场景：弱电/安防/智能化图例库建设，或任何「把一张上百图层的施工图变成干净图块库」的活。

## 它解决什么

| 母库常见毛病 | 本技能的处理 |
|---|---|
| 几十个图层，大半是建筑底图残留 | 删除零引用图层；其余实体并入 `0` 层后删层，颜色自动固化不变色 |
| 插入块后图形跑到几十万坐标外，缩放找不着 | 块内几何整体平移到包围盒居中，插入点即图例中心 |
| 几百个块定义，只用得上十几个 | 只保留目标块 + 递归嵌套依赖，其余全删 |
| 打开一片空白，不知道块在哪 | 清空模型空间，目标块按网格排开，`ZoomExtents` 到位 |

## 前置条件

1. **Windows + 已安装并运行的 AutoCAD**（COM 只能附加到已打开的实例，不另起进程）
2. **pywin32**。清华镜像没有这个包，必须走其他国内镜像：

```bash
python -m pip install pywin32==312 -i https://mirrors.aliyun.com/pypi/simple --trusted-host mirrors.aliyun.com --no-deps
```

3. 自检：`python scripts/cadlib.py <任意dwg> audit`，能打出图层清单即通。

> 不要试图用 `accoreconsole.exe` 或裸 COM 绕路，常被安全策略拒；`ezdxf/ezdwg` 只能读写文件，改不了「块基点」这种需要 CAD 数据库语义的操作。

## 用法

单一入口 `scripts/cadlib.py`，动作用子命令给出。**默认先另存副本，原件不动**。

```bash
# 1 先盘点（只读，不改文件）
python scripts/cadlib.py "D:/母库.dwg" audit

# 2 一条龙提炼
python scripts/cadlib.py "D:/母库.dwg" all \
  --keep "块A,块B,块C" \
  --merge-layers all \
  --out "D:/图库.dwg" \
  --cols 4 \
  --report "D:/报告.json"
```

分步动作：

| 动作 | 作用 |
|---|---|
| `audit` | 只读盘点：图层、每个图层被谁引用、块清单与尺寸。**先跑这个再决定 `--keep`** |
| `clean` | 删除零引用图层 |
| `merge --merge-layers all` | 把其余图层上的实体并入 `0` 层后删层；ByLayer 颜色自动固化为显式 ACI，观感不变 |
| `rebase --keep ...` | 块内几何整体平移到包围盒居中，插入点即图例中心 |
| `slim --keep ...` | 只保留目标块及其递归嵌套依赖，删除其余块定义 |
| `layout --keep ... --cols N` | 清空模型空间，目标块按网格排开 |
| `all` | `clear → clean → merge → rebase → slim → 收尾复清 → layout` |

## 执行流程（必须按序）

1. **audit 盘点**，把「零引用图层清单」和「块清单（含尺寸）」给用户看
2. **确认目标块**：`--keep` 必须是用户点名要保留的块名，**不要自行改名**
3. **在副本上执行**：`all` 默认 `SaveAs` 到 `--out`，原件零改动；要就地改才加 `--inplace`
4. **验收四条**：图层数、块定义数（目标块 + 嵌套依赖 + 3 个系统块）、模型空间块参照数、基点居中偏差
5. 交付时说明哪些块因「被其他块嵌套引用」被一并保留——这类块删了父块会残缺

## 关键约束

- **块名、图例几何一律不改**。只允许两种情况碰几何：基点居中（整体平移）、用户明确要求的等比缩放
- **改图层前先判断颜色来源**：实体颜色为 `256`（ByLayer）时直接改 `Layer` 会跟着新层变色，必须先把 `e.color` 固化为原图层 ACI（脚本已处理）
- **模型空间必须先清空再精简块**：模型空间里的块参照会占住块定义，导致 `Delete()` 报「对象被参照」
- **嵌套块不可删**：父块引用子块时子块必须保留，脚本用递归依赖自动保护

## 已知坑

`references/com-pitfalls.md` 收录 12 条实测结论，其中三条最容易踩：

1. **改块基点用 `entmod` 是假的** —— 改 BLOCK_RECORD 的 10 组码返回 OK，基点纹丝不动。正解是基点留 `(0,0)`、把块内几何平移到包围盒居中
2. **`-PURGE` 不能经 `SendCommand` 发** —— 命令提示对不上就卡死 CAD 主线程（用户得手动按 ESC）。改用 COM 直接删块定义
3. **删除后引用延迟释放** —— 图层/块刚删完会误报「被参照」，等几秒或保存刷库后重试即成功。脚本内置三轮复清

脚本已内置：RPC 拒绝自动重试、文档加载就绪等待、零文档实例兜底。

## 作为 WorkBuddy 技能安装

```bash
# 复制到用户技能目录
cp -r cad-block-library ~/.workbuddy/skills/
```

重开会话后，提到「图例库/图块库/清图层/块基点不对/母库提炼」即会命中。

## 验收标准

- 图层只剩 `0`（有标注点时 `Defpoints` 会保留，属正常）
- 块定义 = 目标块 + 嵌套依赖 + 3 个系统块
- 每个目标块插入 `(0,0)` 后，`GetBoundingBox` 中心偏差 < 1
- 原件文件大小、修改时间未变

## 实测记录

在一张 25 MB、40 图层、180 块定义的弱电安防母库上跑 `all`：

```
图层     40 → 1（只剩 0）
块定义   180 → 17（3 系统 + 13 图块 + 1 嵌套）
冗余块   163 个删除，0 失败
基点     13/13 居中，插入 (0,0) 偏差 0
产物体积 107 KB（原 172 KB）
```
